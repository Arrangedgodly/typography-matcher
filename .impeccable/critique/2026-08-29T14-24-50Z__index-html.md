## What's Working

1. **The strict reveal is engineered, not promised.** Family names mint only inside `open()`; after Escape, zero `.rx-name` nodes remain (verified). The prescription leader-line reveal renders convincingly (origin dot → hairline → arrowhead → name).
2. **The load wait became the signature moment.** Born-covered card, variables swap under the occluder, detent on arrival; reduced-motion collapses it (0 blinds mounted, verified). Measured keyboard save → ready: 261ms.
3. **Input parity is real.** Buttons, ←/→, and drag converge on one funnel; focus is stashed/restored through loading, handed from dismissal to the bar, wrapped inside the pad, and returned to the route on close — the keyboard journey never drops to `<body>`.

## Priority Issues

1. **[P2] Boot-time exhaustion shows a phantom pairing and a silent instrument.** A returning examiner who finished the deck sees the essay in system fallback fonts (Georgia) presenting exactly like a judged pairing, an empty tick rail, and no "61 / 61 examined" count — `advance('first')` returns at `draw.status === 'exhausted'` before `updateMarkers` ever runs, and no pairing is ever applied. Why it matters: the state that should feel like a completed cycle reads as a broken/undefined instrument; the D7 state is a designed state per town-hall. Fix: call `updateMarkers(deck.stats())` on the exhausted path, and treat the wall honestly (persist and re-apply the last-examined pairing beneath the notice, or stand the lane down occluded/empty). Suggested command: `$impeccable harden` (small).
2. **[P2] The judged page's "Save this pairing" button is an inert decoy wearing the instrument's verb.** The essay's own UI chrome (nav label "Prescription", button "Save this pairing") is judged habitat by design — but the button's label collides with the real Save control's vocabulary and semantics; a first-time examiner can click it and receive silence (no handler, intentionally). Why it matters: Error Prevention — the screen's most action-like control inside the judged surface is a dead end; the two live verbs are only at the bar. Fix: keep the habitat, change the verb (e.g. "Read the study") so "Save" exists once on screen; copy-only, no structural change. Suggested command: `$impeccable clarify` (small).
3. **[P3] Pad control targets run small.** `.rx-copy` / `.rx-remove` pills render ≈17–24px tall (0.72rem text + 0.22em padding) — below the WCAG 2.2 §2.5.8 24px target minimum; bar buttons and pills elsewhere are fine. Fix: padding bump to clear 24px without changing anatomy. Suggested command: `$impeccable polish` (small).
4. **[P3] Font prefetch is exported but never wired.** `prefetchPairingFonts` (R2's optional latency hider) has no call site; steady-state swap already measures 261ms, but first-visit slow links carry the full gate. Fix: warm the next draw during deliberation. Suggested command: `$impeccable polish` (small).
